# ch18-capstone — 带链上治理的众筹 DApp（毕业项目参考实现）

> **验证状态**：已在 Foundry 1.8.1 / Solc 0.8.30 下实机验证通过（forge test 25/25 PASS）。写作过程中测试还曾抓出两个真实缺陷（退款状态检查挡住后续出资人、quorum 测试场景构造在达标后出资被拦），修复过程见第 18 章正文。

## 项目是什么

一个众筹合约：出资人向资金池出资；达到目标金额后，**资金如何花由出资人按出资权重投票决定**；未达标则可全额退款。它覆盖了全书后半部分的核心知识点：

- 状态机（Active → Funded / Refunding）——第 7 章
- checks-effects-interactions 与 pull 模式退款——第 11 章
- 自定义错误（custom error）与事件——第 10 章
- 时间控制（`block.timestamp` + forge `warp`）——第 9 章
- 投票权重 = 出资额，无需快照的原因——见下文"设计说明"
- 前端经钱包 → RPC → 合约的完整数据流——第 12 章

## 快速开始

前置：已安装 [Foundry](https://getfoundry.sh)（`curl -L https://foundry.paradigm.xyz | bash`，然后 `foundryup`）。

```bash
cd code/ch18-capstone

# 1. 安装依赖（forge-std，测试与脚本必需）
forge install foundry-rs/forge-std

# 2. 编译
forge build

# 3. 跑全部测试（含 fuzz）
forge test -vvv

# 4. 起本地链
anvil

# 5. 另开终端，用 anvil 默认测试账户之一部署
forge script script/Deploy.s.sol \
  --rpc-url http://localhost:8545 \
  --private-key 0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80 \
  --broadcast

# 输出中的 "Crowdfund deployed at: 0x..." 就是合约地址

# 6. 打开前端：直接用浏览器打开 frontend/index.html，
#    填入合约地址，点"连接钱包"（MetaMask 添加 http://127.0.0.1:8545 网络）
```

预期行为：`forge test` 应显示全部 PASS（含 `testFuzz_Contribute_TotalTracksSum` 的随机运行）。

## 合约设计说明

### 为什么投票权重不需要快照

典型代币投票需要"提案创建时刻的余额快照"，因为余额随时可变。本合约里出资额只在 `Active` 阶段变化，而提案只存在于 `Funded` 阶段——**阶段状态机保证了投票权重不可被刷票操纵**。这是"用状态约束替代快照存储"的设计，省 Gas 也省复杂度，代价是灵活性（募资结束后无法追加出资）。

### 法定人数与通过条件

- 法定人数（quorum）：赞成票权重 ≥ 总募资的 10%。防止少数大户在无人参与时悄悄花掉公共资金。
- 通过条件：赞成严格多于反对。注意"平票即否决"——这是刻意设计，资金支出应取保守解释。
- 投票期固定 3 天（教学用常量；真实协议中此类参数应可被治理修改，但可治理本身又会引入第 17 章"五看"里的权限问题——这个张力留给你在变体中体会）。

### 刻意保留的教学性瑕疵

1. **recipient 收到钱后可以消失**——链上治理只能保证"程序正确"，不能保证"目的正确"。这正是第 1 章"Web3 解决不了现实世界强制执行"的缩影。
2. **`cancel` 任何人可调用**——投票期内取消是常见需求，但"任何人可取消活跃提案"会造成拒绝服务；真实协议会限制取消权限或要求质押。这是一个留给你的改进题。
3. **权重即财阀**——出资 6 ether 的人单票权重 600 倍于最低出资者。去中心化程度 vs 效率的取舍，见第 17 章。

## 测试清单

| 类别 | 用例 | 覆盖点 |
|---|---|---|
| 募集 | contribute 状态更新 / 达标切阶段 / 低于下限回退 / 截止后回退 / **fuzz 总额一致性** | 状态机、输入校验 |
| 退款 | 退款金额与状态 / 达标后不可退款 / 截止前不可退款 | pull 模式、Phase 约束 |
| 提案 | 字段存储 / 未达标回退 / 超库房回退 / 零地址回退 / 空描述回退 | 输入校验、可用资金 |
| 投票 | 权重正确 / 重复投票回退 / 无权重回退 / 逾期回退 | 权重模型 |
| 执行 | 转账与记账 / 法定人数不足回退 / 否决回退 / 投票中回退 / 重复执行回退 / **库房守恒不变量** | 执行门禁、不变量 |
| 取消 | 取消后不可执行 | 提案生命周期 |

## 进阶变体（毕业改造方向）

1. **最小化**：把投票权重从出资额改为 ERC-721"一账一票"（第 10 章手写的 NFT 即可用）。
2. **中等**：给合约加 `revoke`（出资人撤资，需处理已投票权重），补 fuzz 与不变量测试。
3. **挑战**：接入第 13 章的 ERC-4337，让前端用 Passkey 账户出资；或把资金执行改为经时间锁（第 17 章"五看"第 5 项），比较用户体验差异。
